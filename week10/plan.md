# Week10 Mars Voice Recorder Plan

## Summary
`week10` 폴더에 `plan.md`와 구현 파일 `javis.py`를 두는 전제로 진행한다. 프로그램은 실행 중 사용 가능한 마이크 장치를 인식하고, 사용자가 선택한 마이크로 음성을 녹음해 실행 위치 하위의 `records` 폴더에 저장한다. 녹음 파일명은 저장 시점의 날짜와 시간을 기준으로 `년월일-시간분초` 형식으로 생성한다. 보너스 과제로는 시작일과 종료일을 입력받아 해당 범위에 포함되는 녹음 파일 목록을 보여주는 기능을 추가한다.

## Key Decisions
- 기본 구현은 Python 표준 라이브러리를 중심으로 구성한다.
- 단, 과제 조건에 따라 마이크 인식과 실제 녹음 부분은 외부 라이브러리 사용이 가능하므로 이 부분만 별도 모듈에 의존하는 구조로 설계한다.
- 외부 라이브러리 의존 범위는 최소화한다.
  - 마이크 목록 조회
  - 녹음 시작/종료
  - WAV 파일 저장
- 파일 경로 처리, 날짜 문자열 생성, 폴더 생성, 범위 검색, 사용자 입력 검증은 모두 표준 라이브러리로 처리한다.
- 문자열은 기본적으로 작은따옴표를 사용하고, 함수명은 스네이크 케이스를 따른다.
- 저장 위치는 항상 `records` 폴더로 고정하고, 폴더가 없으면 자동 생성한다.

## Expected Features
- 실행 가능한 메인 스크립트 `javis.py`
- 사용 가능한 마이크 목록 출력 기능
- 마이크 선택 기능
- 음성 녹음 시작 및 종료 기능
- 녹음 파일 저장 기능
- 날짜 기반 파일명 생성 기능
- 예외 처리 메시지 출력 기능
- 보너스: 특정 날짜 범위의 녹음 파일 조회 기능

## Public Interfaces
- `ensure_records_directory()`
  - `records` 폴더 존재 여부를 확인하고, 없으면 생성한다.
- `get_timestamped_filename()`
  - 현재 날짜와 시간을 `YYYYMMDD-HHMMSS` 형식 문자열로 만들어 파일명에 사용한다.
- `list_microphones()`
  - 시스템에서 사용할 수 있는 마이크 장치 목록을 조회한다.
- `record_audio(device_index, output_path)`
  - 선택한 마이크 장치로 녹음을 수행하고 지정 경로에 저장한다.
- `list_recordings_by_date(start_date, end_date)`
  - 보너스 기능으로, 날짜 범위에 포함되는 녹음 파일명을 찾아 정렬 후 반환한다.
- `main()`
  - 전체 실행 흐름을 제어한다.

- 사용자가 올바른 장치 번호를 선택하면 녹음이 시작된다.
- 사용자가 녹음을 종료하면 `records` 폴더에 파일이 저장된다.
- 저장된 파일명이 `YYYYMMDD-HHMMSS` 형식을 따른다.
- `records` 폴더가 없을 때 자동 생성된다.
- 잘못된 장치 번호를 입력하면 안내 메시지를 출력하고 종료 또는 재입력 흐름을 따른다.

- 보너스: 조회 범위에 해당하는 파일이 없으면 빈 결과 안내 메시지를 출력한다.

## Assumptions
- 녹음 데이터 저장 형식은 외부 녹음 라이브러리가 무리 없이 저장 가능한 형식으로 선택한다. 일반적으로 WAV가 가장 단순한 기본안이다.
- 과제 조건상 외부 라이브러리는 마이크 인식과 녹음 구현 부분에만 사용한다.
- 날짜 범위 조회는 파일 내부 메타데이터가 아니라 파일명에 포함된 시각 문자열을 기준으로 처리한다.
- 보너스 조회 입력은 구현 단순성을 위해 `YYYYMMDD` 또는 `YYYYMMDD-HHMMSS` 중 하나로 고정하는 방식이 적절하다. 구현 시 한 가지 형식을 명확히 선택한다.
- `records` 폴더는 `javis.py`가 실행되는 현재 작업 디렉터리 기준 하위 폴더로 생성한다.

## Risks and Mitigations
| Risk | Impact | Mitigation |
|------|--------|------------|
| 실행 환경마다 사용 가능한 오디오 라이브러리가 다름 | High | 녹음 관련 코드를 별도 함수로 격리해 의존 범위를 최소화한다. |
| 마이크 장치 이름이나 인덱스 체계가 환경별로 다름 | Medium | 장치 목록을 먼저 출력하고 사용자가 직접 선택하게 한다. |
| 파일명 규칙이 조회 기능과 어긋나면 보너스 기능이 깨짐 | Medium | 저장과 조회 모두 같은 타임스탬프 생성 규칙을 공유하게 설계한다. |
| 잘못된 날짜 입력으로 조회 로직이 실패할 수 있음 | Low | 입력 형식을 고정하고 `datetime` 기반 검증을 추가한다. |
